Review document · F3K / F5K competition timing system

Every rule the system enforces

This is a working timing and scoring system for hand-launch glider competitions. Each rule below is something it actually does today, and each one was a decision made by someone still learning the sport. The marked ones are the point — they need someone who has run competitions to say whether they are right.

01

What the system is, and is not

R-01
Verified

The system times and records; GliderScore remains the scorer of record. Results export as a GliderScore-compatible file and the CD scores there. The built-in scoring exists so the CD can see live standings during the day.

R-02
Judgement call

The built-in scoring engine is a second opinion, not an authority. It implements the task rules independently. If it and GliderScore disagree, GliderScore is right and we have a bug.

Worth challenging

It has never been validated against a full scored competition. Until it has, how much should a CD trust the live leaderboard in front of the pilots?

R-03
Verified

Everything works with no internet. The field system is three isolated networks with no uplink. Nothing depends on a cloud service or a phone signal.

02

The round: prep, working window, landing

R-04
Judgement call

A round runs prep → working window → landing window. Defaults are prep 2:00, landing 0:30, with a 30 s gap between heats and between rounds, 45 s focus time and a 15 s final count.

Worth challenging

Two minutes of prep is shorter than the three minutes F3K commonly uses, and it is what every new competition starts with unless the CD changes it. If 3:00 is standard, this is a one-line change.

R-05
Judgement call

The base station starts the round; the timekeeper cannot. While a timer is connected, its start buttons are locked. Every timer in the heat starts on the same broadcast, so the group is on one clock.

Why

Independent starts drift, and the pilot flying nearest the CD gets a different window from the one at the far end of the line.

Worth challenging

A timekeeper who wants to start their own pilot cannot. Should there be a manual override for a timer that has lost the link?

R-06
Judgement call

If the start signal is lost, the timer opens the window itself 250 ms after its own prep clock hits zero. That clock is re-synced from the base every second through the last ten, so its zero is accurate to about one packet.

Why

A dropped packet must never cost a pilot part of their window. Waiting even a second for a start that may never come opens the window late for that pilot alone.

Worth challenging

A pilot on a degraded link could start a fraction before the rest of the group.

R-07
Judgement call

The CD can skip the prep countdown forward — jumping to "one minute to go" when the line is ready early. Only during prep, never during the window.

R-08
Known gap

The landing window is a countdown, and nothing more. The timer shows it and moves to results at zero. The system does not enforce anything about landings — it does not know where a model came down, and applies no landing bonus or penalty. If your rules score landings, that happens in GliderScore.

03

Launching and jumped starts

R-09
Judgement call

A launch before the window opens is recorded, flown, and then invalidated. The right-hand button unlocks two seconds before the window opens. A flight started there runs on screen marked JUMPED in red, and is automatically scratched when it stops — it never counts and never reaches the results.

Why

The alternative is refusing to start the clock, which leaves the timekeeper fighting the device while the model is already in the air.

R-10
Judgement call

A jumped start is a note to the CD, never a stored flight. It appears on the run screen. It is not in the database and cannot appear in results.

Worth challenging

Should a jumped start be a scoring penalty rather than a discarded flight? Right now the pilot simply loses that launch. Some readings say it should cost more.

R-11
Judgement call

Why two seconds. Wide enough to catch a genuine early launch, narrow enough that it is not a general "start early" button. The unlock stays open at zero, because the local clock can reach zero up to a second before the start signal arrives — and that gap is exactly when a pilot jumps.

04

Flights and scratching

R-12
Verified

A flight is timed launch to landing by the timekeeper's button presses, recorded to hundredths, and sent to the base station immediately.

R-13
Verified

Up to ten flights per pilot per round are recorded. More launches than the task allows are still recorded, but not scored — see R-20.

R-14
Judgement call

Scratching discards the most recent flight not already scratched. The timekeeper presses left, then confirms within two seconds. There is no way to scratch an earlier flight from the timer.

Worth challenging

Is "most recent" always what a caller means? A caller who realises two flights later that one was invalid cannot fix it on the timer — the CD must do it on the base station.

R-15
Judgement call

A scratched flight is kept and marked, never deleted. It shows struck through in red on the results screen, and is excluded from both scoring and the export.

Why

An audit trail if a pilot disputes the call — and a deleted flight would be silently re-created by the end-of-round safety resend (R-27).

R-16
Judgement call

A scratch is the timekeeper's decision and needs no CD confirmation. The timer already requires a deliberate confirm press.

Worth challenging

At a serious competition, should a scratch require the CD to countersign? Currently the caller's word is final and the CD only sees the result.

05

Task scoring

R-17
Verified

Flight times are truncated, not rounded — to one decimal by default. 59.98 s scores 59.9, not 60.0. This matches GliderScore.

R-19
Known gap

Poker is not really implemented. A declared target is central to the task, and the system never records a declaration. It simply takes the achieved times and scores the best few. A pilot who declares 3:00 and flies 2:30 should score nothing for that flight; here they score 2:30.

The single biggest known gap

It needs either a way for the timekeeper to enter a declaration on the timer before the launch, or an explicit decision that Poker is scored by the CD in GliderScore and the timer only records times.

R-20
Judgement call

Where a task limits launches, extra flights are ignored in the order flown — the first few are kept, later ones dropped. They remain recorded and visible.

Worth challenging

Should a pilot who over-launches keep their best allowed flights instead? Keeping the first ones is the stricter reading, but it is a reading.

R-21
Judgement call

Target-matched tasks pair the longest flight with the largest target, second-longest with second-largest, and so on — each scoring the lesser of flight and target. This maximises the pilot's score.

Worth challenging

It assumes the pilot always gets the most favourable assignment. If your rules require the pilot to nominate which flight targets which slot, this is wrong.

R-22
Judgement call

An unknown task scores every flight rather than failing. If a round references a task the system does not know, it counts all flights instead of crashing the results page.

Why

A scoring page that fails mid-competition is worse than one that is generous and visibly wrong.

06

F5K height bonus

R-23
Verified

Bonus points by motor-cut height, relative to a reference height (default 60 m, settable per competition and per round).

Height vs referencePoints
Below+0.5 per metre, no limit
1–10 m above−1 per metre
11 m+ above−1/m for the first 10 m, then −3 per metre

15 m above reference is −10 for the first ten metres and −15 for the next five: −25 points. Verified against GliderScore's own bonus table and the NZ Nationals 2026 data.

R-24
Judgement call

The bonus applies only to a flight that counts and is at least 30 seconds (configurable). A flight that does not score gets neither bonus nor penalty.

Worth challenging

A pilot who launches very high and lands immediately escapes the height penalty entirely, because the flight is too short to qualify. Intended, or should the penalty apply regardless?

R-25
Known gap

Heights are entered on the timer after the round, one flight at a time, and can be overridden by the CD. Each height records whether it came from the timer or the CD. Heights are not exported — the file carries flight times only, and GliderScore applies the bonus from heights the CD types there. Confirmed against a scored F5K competition, but it does mean heights are entered twice.

07

When things go wrong

R-26
Verified

Every flight, scratch, height and pilot selection must be acknowledged by the base station. The timer holds each message until the base echoes it back, and retries until it does — through a dropped link, a base station restart, or a flat battery on the network.

R-27
Verified

At the end of every round the timer re-reports the whole round from its own memory. Anything the base missed is recovered; anything it already has is recognised and ignored. Recovered flights are flagged loudly, because the log changed after the round ended.

R-28
Verified

The timer keeps the last three rounds in permanent memory, written flight by flight as they happen. A timer that loses power mid-round keeps everything already flown, and the round can be recovered without the base station.

R-29
Judgement call

A duplicate means: same pilot, same group, same time to the millisecond. Two genuinely identical flights in one group are treated as one.

Worth challenging

Two flights matching to the millisecond is vanishingly unlikely — but not impossible, and if it happened the pilot would silently lose one.

08

Normalisation, drops and standings

R-30
Verified

Within a group, the best raw score scores 1000 and everyone else scores their score ÷ best × 1000, truncated to one decimal.

R-31
Judgement call

A group where nobody scores gives everyone zero, not 1000. If no one posts a time, no one gets the winner's points.

R-32
Judgement call

A round with no flights at all does not count toward the competition, and is not a drop candidate — it simply did not happen.

R-33
Verified

Drop scores are configured per competition — drop one becomes active after round n, and so on for up to three. The lowest scores are dropped.

R-34
Judgement call

On tied scores, the earliest round is dropped.

R-35
Judgement call

Ties in the standings break on the last round flown, then working backwards — FAI style.

Worth checking

The tie-break compares each round's score including rounds that were dropped. A stricter reading might compare only counting rounds.

09

The draw

R-36
Judgement call

Round one is drawn at random; later rounds are seeded by reverse standings, snaked across groups — so the leaders are spread out rather than all flying together.

R-37
Judgement call

The multi-round draw optimises for every pilot flying with every other pilot at least once. Meeting a new pilot is weighted heavily; repeat meetings are mildly discouraged.

R-38
Judgement call

Back-to-back flying is avoided — a pilot in the last group of one round and the first group of the next gets no break. With three or more groups this is treated as effectively mandatory; with two groups it is only a preference, because forcing it would freeze the group composition for the whole competition.

Worth challenging

Is one group's gap enough rest, or should it be two?

R-39
Judgement call

The draw warns if there are not enough non-flying pilots to timekeep — assuming one timekeeper per flying pilot, drawn from those not in the group.

Worth challenging

This assumes pilot-timekeepers. A competition with dedicated helpers does not need the warning at all.

R-40
Judgement call

Group sizes differ by at most one, and the earlier groups get the extra pilot.

10

Audio

R-41
Verified

The cues are GliderScore's own, extracted from its database — the same announcements and beeps at the same times, so a pilot hears what they are used to.

R-42
Judgement call

Working times GliderScore has no profile for get a generated cue schedule rather than running in silence.

R-43
Judgement call

The last ten seconds of the working and landing windows are beeps, not spoken numbers. Spoken counts overlapped each other at one-second spacing.

R-44
Judgement call

The spoken cue "to land" is deliberately suppressed. It fired one second before the landing beeps and clipped them. "Pilots must land" already makes the call 17 seconds earlier, and the timer shows the landing clock.

R-45
Verified

Landing cues are re-anchored to the competition's actual landing window, not the length in GliderScore's profile.

R-46
Verified

Audio latency was removed rather than compensated — cues fire on the beat with no offset. Bluetooth speakers are the exception: they add 100–200 ms that cannot be removed and must be dialled out per speaker.

11

Deliberate omissions

Things the system does not do, on purpose. Each is a candidate for challenge — better you tell us which of these matters than a CD discovers one mid-competition.

  • No landing scoring or bonus.
  • No Poker declarations — the largest gap (R-19).
  • No penalties of any kind. No airframe, safety or late-landing penalties. There is a penalty field in the database and nothing writes to it.
  • No fly-off handling. A fly-off is run as ordinary extra rounds.
  • No airframe or model registration, so no model-change rules.
  • No wind or weather record, and no round abandonment or re-fly workflow. A round is re-flown by deleting the flights and running it again.
  • No handicapping, junior or age classes in scoring — pilots are one field.
  • Timekeeper assignment is not tracked; the draw only warns whether enough pilots exist to fill the role.
12

The five questions most worth your time

In priority order. If you read nothing else, these are the calls where being wrong would matter most on the day.

  1. Poker — we never record a declaration

    Task E scores achieved times instead. Is that an acceptable simplification, or does it make the task meaningless? R-19

  2. Jumped starts cost only the launch

    The flight is discarded and nothing more. Should it carry a scoring penalty? R-10

  3. Over-launching drops flights by order, not quality

    The first allowed flights are kept and later ones discarded. Is that the right reading? R-20

  4. Target matching always favours the pilot

    We pair the longest flight with the largest target. Is that how these tasks are actually scored? R-21

  5. A very high launch can escape the height penalty

    If the flight is too short to qualify for the bonus calculation, no penalty applies. Should it? R-24
